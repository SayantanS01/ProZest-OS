# M09 Step 2.17G — Synthetic nested exception guard

**2026-11-24 · PASS · main at 652dc29 plus local changes**

The experiment asked whether a second fatal report can stop the CPU before the dispatcher touches the graphical console. One QEMU vCPU completed the first report, entered the dispatcher with a different vector and halted inside the reporter.

## Verified results

- ELF64 x86-64, first load segment at 0xffffffff80000000, kernel_main at 0xffffffff80001000. Disassembly of the linked kernel contained no LGDT, LTR, LIDT or STI.
- Recompiled host structural tests passed 31/31 and handler identity tests passed 36/36, both normally and under ASan plus UBSan. Leak detection was disabled because LeakSanitizer failed under the sandbox tracer. The host tests never invoked the assembly exception stubs.
- The byte-for-byte runtime log below proves the first call returned. Reaching the start marker also required successful in-guest preparation, structural checks and exact handler identity validation.
- The reporter uses a memory XCHG on panic_active. The old value selects the branch. Relaxed ordering suffices for ownership of this single flag. The repeated-entry branch writes to port 0xE9 and ends in CLI at 0xffffffff8000218c, HLT at 0xffffffff8000218d and a backward jump at 0xffffffff8000218e.
- QEMU reported RIP 0xffffffff8000218e, CPL=0, HLT=1 and RFLAGS=0x46 (IF clear). In exception_dispatch the call to the reporter at 0xffffffff80001e7e precedes the first graphical call at 0xffffffff80001e83. The observed second branch halts inside the callee, before that graphical call can execute.
- CS=0x28, SS/DS/ES=0x30, TR=0x38, GDTR=0xffff80001fe67000 limit 0x47, IDTR=0 limit 0. These selectors and limits match the inherited configuration. The single boot transcript and live halted CPU with reboot disabled showed no unexpected restart.

## Problems resolved

The compiler placed a helper ahead of kernel_main in the initial build. Giving kernel_main its own input section fixed the entry address. Fixed ISO dates alone left a varying GPT identifier. Setting SOURCE_DATE_EPOCH produced identical images. The sandbox denied the monitor socket bind, so the VM ran with approval. The initial optical-drive configuration stalled during firmware boot. A virtio-SCSI CD-ROM with explicit boot priority booted successfully. The monitor confirmed KVM was available in that execution environment.

## Concepts and interview questions

1. **What does the guard remember?** The first caller changes one word from zero to one. Every subsequent caller sees that someone has already started fatal reporting.
2. **Why use an atomic exchange?** Reading and setting the flag in one operation prevents two callers from both observing zero. This single-vCPU experiment exercises repeated entry only.
3. **Why does RIP point one byte past HLT?** The saved instruction pointer identifies the next instruction. HLT=1 and the jump back to CLI identify the waiting loop.
4. **Why bypass graphical logging?** A second failure may occur while the console is already updating its state. The nested branch only needs simple port writes and a halt.
5. **What would hardware delivery additionally test?** The CPU must find a valid gate, resolve its code selector, choose a stack and build the exception frame. Direct C calls supply arguments without exercising any of those steps.

## Proposed next milestone — review the descriptor transition

This is a design proposal. Hardware delivery, IST switching, simultaneous entries on multiple CPUs and recovery from machine checks remain unverified.

The experimental installer currently changes GDTR, reloads segments and TR, then loads IDTR. At the observed handoff IDTR is empty. CLI leaves NMI and machine-check exposure, and a fault while delivering another exception can require the double-fault gate. A usable IDT alone is insufficient if its selector or stack is invalid for the active GDT and TR. See the interrupt handling and machine-check chapters of the [Intel system programming manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html).

1. Establish the handoff contract first. Record the live code descriptor and stack mappings. Require an upstream valid IDT and known-good TSS/IST for continuous coverage from handoff, or explicitly document that the period before the first usable gate cannot be protected by kernel reordering. The observed TR base of zero with limit zero gives no evidence of usable inherited IST slots.
2. Model a temporary IDT with fatal handlers and a bridge GDT containing compatible code descriptors at both the inherited and target selectors. Validate descriptor types, limits, mappings, stack bounds and writable TSS descriptor storage offline. Keep all transitional objects resident.
3. Specify every intermediate state. Temporary gates using the inherited selector must resolve before and after the GDTR change. With IST zero, same-privilege delivery depends on a healthy current stack. If the design requires double-fault survival after stack loss in this phase, require a verified predecessor IST or revise the bootloader handoff. Treat that gap as a review blocker. Load the prepared TR against the bridge before selecting any new IST slots. Switch to the final gates only when their CS and stacks are valid. Preserve selector compatibility until final segment reloads and table changes finish. Account for the TSS busy bit and cached TR when planning any final GDT replacement.
4. Review separate fatal paths for NMI (IST2), machine check (IST3) and double fault (IST1), including repeated events, independent mapped stacks, minimal assembly entry, register/frame layout and zero reliance on console locks. Some machine checks preclude reliable software handling. Keep maskable interrupts disabled throughout.
5. Require a phase-by-phase selector/TR/stack matrix and host negative tests before reviewing activation. After approval, test each boundary in a disposable VM, capture delivery and frame evidence independently and define reset or missing evidence as failure. Keep hardware validation and recovery claims separate from these synthetic results.
