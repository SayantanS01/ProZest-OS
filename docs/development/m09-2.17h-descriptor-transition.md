# M09 Step 2.17H — Descriptor transition preparation

**2026-11-24 · PASS on QEMU/KVM · preparation only.** Step 2.17G established synthetic panic re-entry. This checkpoint prepares persistent hardware layouts and measures the inherited CPU state on both sides of preparation. Actual descriptor loading and hardware delivery await review.

## Architecture and audit

The old descriptor_install.S starts with LGDT and ends with LIDT. In between, the inherited IDT is empty, selectors 0x28 and 0x30 exceed the new limit, and FS/GS retain inherited selectors. Loading GDTR alone leaves hidden segment caches intact. A fresh gate lookup or selector reload consults the new table. CLI only clears IF. An NMI or a fault during the far transfer can therefore arrive before there is a usable gate.

The bridge has seven eight-byte slots, limit 0x37. It provides ring-zero code at 0x28 and 0x08, data at 0x30 and 0x10, and zeros elsewhere. Two separate 256-entry temporary IDTs have 32 present interrupt gates each, IST zero, attributes 0x8E and zeroed unused entries. Each temporary assembly stub emits T plus its two-digit hex vector and LF on port 0xE9, then halts. It needs no software stack access or graphical logger. The processor must still push its own frame.

| Future state | Active GDT | Gate selector | Emergency delivery stack |
|---|---|---|---|
| Limine entry | inherited | empty IDT | unavailable |
| Early IDT | inherited | 0x28 | current RSP |
| Bridge | bridge | 0x28 | current RSP |
| Second temporary IDT | bridge then final | 0x08 | current RSP |
| After LTR | final | 0x08 | current RSP until final LIDT |
| Final IDT | final | 0x08 | IST1 for #DF, IST2 for NMI, IST3 for #MC, otherwise current RSP at CPL0 |

```text
empty IDT → early IDT → bridge GDT → reload segments → second IDT
          → final GDT → load final TR → final IDT
```

The early IDT can be built and validated independently before allocating time to the other checks. Published temporary tables are revalidated in place on repeat preparation. Full preparation leaves the early IDT intact. The experimental entry checks for fresh final objects before invoking the legacy initializers, which can rewrite existing storage. Future activation code must exclude those initializers after publication. A second immutable gate image removes any need to patch live 16-byte gates. Loading TR directly from the final GDT gives the hardware a single authoritative busy bit.

## Activation proposal for review

1. At BSP entry retain the Limine stack and its mappings. Verify the supported revision, CPL, IF, four-level paging, selector access rights, zero live FS/GS bases and canonical writable stack headroom. Keep all old and new storage mapped. Exclude concurrent preparers. Check CET is off before using a synthetic far-return frame. Reject an unsupported handoff. Keep verbose logging off the initial critical path.
2. Prepare and validate the early IDT. Load its ten-byte operand with LIDT while Limine's 0x28 still names valid 64-bit code. Until this instruction completes even a valid handler cannot receive an interrupt through the empty IDT. For continuous coverage the predecessor must provide working gates and stack state.
3. With early fatal delivery available, prepare the final objects once and validate the bridge and second temporary IDT. Verify current stack capacity for the largest hardware frame, alignment padding, far-return frame and nested entries. Validate RX handler and RW stack/table mappings before activation. Reserve the boot stack throughout. No allocator, logging lock, userspace or privilege transition belongs in the switch.
4. Preload canonical operand pointers and continuation address into registers. Keep IF clear. Use CLD for the C ABI. LGDT bridge. Cached TR=0x38 temporarily has no addressable slot in the bridge. Every gate still uses IST0 at CPL0, so none should use this TR for stack selection.
5. PUSHQ target selector 0x08, PUSHQ canonical continuation RIP, LRETQ. At the continuation MOV 0x10 into AX, then MOV AX into DS, ES, FS, GS and SS individually. The bridge supports both selector pairs throughout. Reloading FS/GS may replace their bases. This design admits only live zero bases and uses zero-base data descriptors. Preserve KERNEL_GS_BASE and avoid SWAPGS. A future nonzero TLS/per-CPU base requires a revised policy. Do not rely on the MOV SS interrupt shadow for safety.
6. LIDT the second temporary IDT. Its gates use 0x08, valid in both bridge and final GDT. LGDT the final 40-byte GDT (limit 0x27). Now every live code/data selector fits and all temporary gates still use the current stack.
7. MOV 0x18 into AX. LTR AX once against the writable available descriptor (0x89) for the resident 104-byte TSS. Expect 0x8B after hardware marks it busy. LIDT the final table (limit 0xfff) immediately afterward. Only now do the three assigned vectors select dedicated stacks. Leave IF clear.
8. Read SGDT, SIDT, STR, segment selectors, MSRs and flags. Compare actual operands to persistent objects and check cached TR base/limit in QEMU. Verify final exception offsets and IST indices. Accessed-bit writes may change code/data access bytes from 0x9A/0x92 to 0x9B/0x93 in the table actually used for the load. LGDT alone does not set these bits. Post-install checks must allow the accessed bit and require a busy TSS instead of reusing strict pre-install checks.
9. First review and run a separate activation-only ISO. Use bounded per-stage debugcon markers and save monitor RIP, stack, GDTR, IDTR, TR, emulator reset log and last complete marker. A temporary Txx marker identifies a reached fatal gate. Missing output or reset is inconclusive about the vector. After successful readback, use separate disposable boots for a genuine kernel invalid opcode and a controlled access to a verified unmapped test page. Check vector, saved instruction location and, for #PF, CR2 and error bits. Instrument frame evidence first. Review dedicated-stack and NMI testing separately.

A damaged current stack can prevent frame delivery even to the temporary #DF gate. Faults during #DF delivery may shut the processor down. Reusing an IST top on repeated delivery can overwrite an older frame. NMI delivery is independent of IF. CR4.MCE was clear here, and some machine checks can shut down the CPU irrespective of an installed gate. Hardware recovery, SMP, ring changes and IRQ vectors 32–255 are outside this checkpoint. Architecture references: [Intel SDM, volumes 2 and 3](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html) and [AMD64 APM volume 2](https://docs.amd.com/v/u/en-US/24593_3.44_APM_Vol2).

## Interview review

1. **Why use a bridge GDT?** The same table can resolve both sets of selectors during the switch.
2. **Why load an IDT first?** Limine handed over an empty one. A valid early gate gives the CPU a destination sooner.
3. **Why two temporary IDTs?** The gate's code selector must change before the old selector disappears. A whole-table switch avoids a partly rewritten gate.
4. **What does IST zero mean here?** Same-privilege entry uses the current stack for the interrupt frame.
5. **Can a stackless handler survive a broken stack?** Hardware pushes the frame before the first handler instruction. That push can fail.
6. **Does CLI solve NMI delivery?** No. It masks ordinary interrupts through IF.
7. **Why inspect FS/GS bases separately?** Their effective addresses can include a base that the selector value alone cannot tell you.
8. **Who sets the TSS busy bit?** The CPU does when LTR accepts an available TSS descriptor.
9. **Why inspect the ELF as well as the logs?** The ELF identifies handler addresses, intended permissions and compiled instructions. The logs show what the running CPU observed.
10. **What would prove genuine exception delivery?** A separate activation test with a CPU-generated exception and matching handler, frame and register evidence.
