# M09 Step 2.17J — Genuine invalid-opcode delivery

**2026-11-24 · PASS on QEMU/KVM.** Step I established descriptor ownership. This experiment executes one UD2 after verifying the active tables and compares the frame left by the CPU with the instruction address and interrupted stack recorded by the trigger.

## Delivery and frame

The linked ud_fault_site contains 0F 0B at 0xffffffff80001957. UD2 raises a fault, so saved RIP identifies the instruction itself. The active vector-6 interrupt gate resolves through selector 8 to exception_stub_6. The final structural validator checks IST zero, and the identity validator checks the exact stub address. At CPL0 the processor uses the current stack, aligns it and pushes five eight-byte slots. Vector 6 supplies no error code. [Intel instruction reference](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2b-manual.pdf) and [AMD system programming manual](https://www.amd.com/content/dam/amd/en/documents/processor-tech-docs/programmer-references/24593.pdf).

```text
handler entry RSP +  0   RIP
                  +  8   CS
                  + 16   RFLAGS
                  + 24   interrupted RSP
                  + 32   SS
```

The stub captures RSP in RSI before touching the stack, clears DF, sets EDI to 6, aligns RSP down to 16 and passes that address in RDX. CALL pushes its return address below the hardware frame, satisfying the AMD64 C ABI. The C handler validates the frame, then invokes the established fatal dispatcher. Its legacy second argument is ignored for vector 6. The separate error-code stubs retain their existing interface.

## Interview review

1. **Why UD2?** It is an architecturally defined instruction for provoking #UD.
2. **Which IDT slot does the CPU fetch?** Slot 6.
3. **Why does saved RIP point at UD2?** A fault records the instruction that caused it.
4. **What is the first frame word?** Saved RIP. Vector 6 has no hardware error code.
5. **Why keep the entry RSP?** It locates the frame even after software aligns the stack.
6. **What is saved RSP?** The stack pointer immediately before the fault.
7. **Why align before CALL?** The compiled handler expects the System V stack convention.
8. **Did this use a dedicated emergency stack?** IST zero and CPL0 delivery used the existing kernel stack.
9. **How do we know reporting finished?** Debugcon recorded completion and the monitor found the CPU halted in the dispatcher.
10. **Could this handler resume execution?** Its path is fatal. Returning to the same UD2 would fault again.
