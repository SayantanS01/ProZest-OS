# M09 Step 2.17I — Controlled descriptor activation

**2026-11-24 · PASS on one QEMU/KVM BSP.** ProZest loaded its permanent GDT, TSS and IDT and returned from the assembly installer to C on the inherited boot stack.

## Executed sequence

| Completed operation | Active GDT / TR / IDT | Delivery conditions |
|---|---|---|
| Verify revision, LAR rights, selectors, zero FS/GS bases, IF clear, four-level mode and CET off | Limine / inherited / empty | Empty-IDT interval persists |
| Prepare early gate image, LIDT early | Limine / inherited / early | Selector 0x28, current stack |
| Build and validate permanent and bridge storage once, CLI, CLD, LGDT bridge | bridge / inherited / early | Both selector pairs resolve |
| PUSHQ 0x08, PUSHQ local continuation, LRETQ, MOV 0x10 into AX and reload DS, ES, FS, GS, SS in order | bridge / inherited / early | Both pushes consumed, bases zero |
| LIDT second temporary image | bridge / inherited / second | Selector 0x08, current stack |
| LGDT permanent | permanent / inherited / second | All live segment selectors fit |
| MOV 0x18 into AX, LTR AX | permanent / permanent / second | Hardware marks writable TSS descriptor busy |
| LIDT permanent, RET | permanent / permanent / permanent | #DF uses IST1, NMI IST2, #MC IST3 |

Assembly debug markers run after their operations, using only AL and R8. The four pointer arguments stay in their original caller-saved registers. No intermediate C call or callee-saved register spill is required. The temporary gates ignore inherited TR. The selector reloads happen against the bridge. A descriptor load may mark a code/data descriptor accessed there. Changing GDTR does not refetch the cached descriptors. The post-check therefore allows either accessed-bit value and requires the permanent TSS access byte to equal 0x8B. Its other structural checks and exact final handler identities remain strict. [Intel architecture manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html) and [AMD architecture manual directory](https://www.amd.com/en/search/documentation/hub.html).

## Lessons and limitations

The preparation validator correctly rejects a busy TSS. Sharing its layout checks while selecting a phase-specific access-byte policy resolved this incompatibility. The original installer could leave no usable gate across the switch and was excluded. Both activation boots completed. No fault injection was performed. The initial empty IDT, dependency on the current stack before final LIDT, and asynchronous NMI or machine-check exposure remain. No hardware IRQ or userspace path is ready.

1. **What does LGDT change?** The address and limit used for future GDT lookups.
2. **Why a far return?** It reloads CS and transfers execution to the intended 64-bit continuation.
3. **Why a bridge?** It contains valid old and new code/data selectors while both are needed.
4. **Why two temporary IDTs?** They change the gate selector without patching a live gate.
5. **Why reload FS/GS?** Their selectors must fit the final GDT, and their effective bases must follow the chosen zero-base policy.
6. **What proves LTR completed?** The active selector, cached permanent TSS address and limit, and busy byte agree.
7. **What does IST zero mean here?** At CPL0 a gate uses the current stack.
8. **Why preserve IF clear?** The kernel has no hardware IRQ handling yet.
9. **Why is RIP beyond HLT?** HLT waits with the instruction pointer at the next instruction.
10. **What remains to test?** The processor must actually select a gate, build a frame and reach the handler during a real exception.
